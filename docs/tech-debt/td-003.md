# TD-003 – The admin API has no authentication or authorization

- **Status:** Resolved (2026-10-11)
- **Added:** 2026-10-11
- **Area:** API (`UsersController`, `RolesController`, `PermissionsController`, `ScopesController`, `ClientsController`)

## Current state

- All endpoints under `/api/users`, `/api/roles`, `/api/permissions`, `/api/scopes` and `/api/clients` can be called by anyone who can reach Authora. There is no authentication and no permission check.
- They are mapped in every environment, not only in Development.

## Why

Authentication needs the OAuth runtime (sign-in, Sessions, tokens), which is planned for a later phase. The permission checks (US-032) need these tokens and the `Permissions` constants, which do not exist yet either. See the open decisions in [identity-access-plan.md](../identity-access-plan.md#open-decisions).

## Impact

- Anyone with network access can, for example, give themselves the administrator Role, create a Client Secret, or delete Users.
- Authora must not be run where untrusted clients can reach it until this entry is resolved.

## Resolution

- The admin API only accepts Access Tokens issued by Authora (`Authorization: Bearer`), checked in the database on every request (`AccessTokenAuthenticationHandler`). The Session cookie is not accepted, so cross-site requests from a signed-in browser cannot call it.
- Every admin controller requires the policy `admin-api`: the token must have the System Scope `authora.admin`. Every action additionally requires a Permission (`[Authorize(PermissionNames.Users.Create)]`), which the User must have through one of their Roles (`PermissionAuthorizationHandler`, `PermissionEvaluator`). The administrator Role always has all Permissions.
- `IdentitySeeder` seeds the Permissions of `PermissionNames`, the administrator Role and the `authora.admin` Scope at startup, and creates the first administrator from `Authora:Bootstrap` (US-003). See [identity-access-plan.md](../identity-access-plan.md#admin-api-access).
- The details of `GET /health` are still public, see [TD-010](td-010.md).
