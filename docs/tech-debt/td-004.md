# TD-004 – The last-administrator check is not safe against concurrent requests

- **Status:** Open
- **Added:** 2026-10-11
- **Area:** Users (`AdministratorGuard`, `DeactivateUserService`, `DeleteUserService`, `RemoveRoleService`)

## Current state

Before an administrator is deactivated, deleted or loses the administrator Role, `AdministratorGuard` counts the other administrators who can sign in. If there are none, the request is rejected with 409.

The count and the following save are not protected by a lock or a transaction. This is a check-then-act pattern.

## Why

The check covers the common case: a single administrator removing their own access. Making it safe against concurrent requests needs locking in the database, which the repositories do not support yet (each one saves on its own and there is no shared transaction).

## Impact

With two administrators A and B, two requests at the same time, e.g. "deactivate A" and "delete B", can both see one other administrator, both pass the check, and both save. Afterwards, no administrator is left.

Recovering requires direct access to the database, or the bootstrap of a new administrator (US-003). The risk is low, because it needs two concurrent administrative requests that target the last two administrators.

## How to resolve

Run the check and the save in one transaction that serializes changes to administrators. Options:

1. **Advisory lock (recommended):** at the start of the transaction, call `SELECT pg_advisory_xact_lock(<constant key>)`. Every request that can remove administrator access waits for the previous one, so the count is always current. The lock is released automatically at the end of the transaction.
2. **Serializable transaction:** run the check and the save with `IsolationLevel.Serializable` and retry on serialization failures (`40001`).
3. **Row locks:** load the administrators with `SELECT ... FOR UPDATE` before counting them.

All options need a way to run several repository calls in one transaction, e.g. a unit of work or a transaction on `AuthoraContext` that the services can use.
