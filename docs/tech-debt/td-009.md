# TD-009 – Every Confidential Client can introspect every Access Token

- **Status:** Open
- **Added:** 2026-10-11
- **Area:** OAuth (`IntrospectTokenService`, `/oauth/introspect`)

## Current state

Any enabled Confidential Client that authenticates at `/oauth/introspect` gets the details of any active Access Token: the User Id (`sub`), the Client and the Scopes. Access Tokens have no audience, so Authora cannot tell for which resource server a token is meant.

## Why

Resource servers need to introspect tokens issued to other Clients (the Client calls the API, the API introspects). Restricting this needs a way to tell which resource server may see which token, e.g. an audience or resource indicators (RFC 8707). Neither exists in the model yet.

## Impact

- A Confidential Client that obtains an Access Token of another Client can learn which User and Scopes it belongs to. It cannot use the token to get new tokens, and it would need the token in the first place.
- Any Confidential Client can act as a resource server for any Scope.

## How to resolve

1. Model resource servers, e.g. as a flag on Confidential Clients or as their own entity, together with the Scopes they serve.
2. Only let a resource server introspect tokens that contain at least one of its Scopes, and return only those Scopes. Otherwise return `{"active": false}`.
3. Optionally support resource indicators (RFC 8707), so a token is issued for a specific resource server (`aud`).
