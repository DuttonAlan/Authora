# ISS-002 – Updating a User accepts blank First and Last Names

- **Status:** Resolved (2026-10-11)
- **Found:** 2026-10-11, in the code review of `feature/add-identity-endpoints`
- **Area:** Users (`User`, `UpdateUserService`)

## Problem

`PUT /api/users/{id}` accepted a First Name or Last Name that only contains whitespace, e.g. `{"firstName": "   "}`. `UpdateUserService` trimmed it and saved an empty string.

Creating a User with the same value was correctly rejected, so a User could end up in a state that `User.Create` does not allow.

## Impact

- Users could be saved with an empty First Name or Last Name.
- The rule "a name is not empty" depended on the endpoint that was used, instead of being enforced by the `User` entity.

## Cause

- `User.FirstName` and `User.LastName` had public setters, so the service could set any value. Only `User.Create` checked for empty names.
- The request validation does not catch it on update. On create, `[Required]` rejects whitespace-only strings. On update, the fields are optional, so they have no `[Required]`, and `[StringLength(..., MinimumLength = 1)]` accepts `"   "` because it has a length of 3.

## Fix

- `User` has new methods `SetFirstName` and `SetLastName`. They trim the value and throw `ArgumentException` (400) if it is empty, only whitespace, or longer than `User.NameMaxLength` (50).
- `FirstName` and `LastName` now have private setters, so they can only be changed through these methods. `User.Create` uses them as well, which also adds the length check there.
- `UpdateUserService` calls `SetFirstName` and `SetLastName` instead of setting the properties.
- The new constant `User.NameMaxLength` replaces the hard-coded `50` in `UserConfiguration`, `CreateUserRequest` and `UpdateUserRequest`. The database model is unchanged.

## Verification

Tested manually against a fresh database:

| Request | Result |
|---|---|
| Update with `{"firstName": "   "}` | 400, `(Parameter 'firstName')` |
| Update with `{"lastName": "\t"}` | 400, `(Parameter 'lastName')` |
| Update with `{"firstName": "  Janet  ", "lastName": " Smith "}` | 204, saved as `Janet` and `Smith` |
| Create with `"firstName": "   "` | 400, `The FirstName field is required.` (unchanged) |
