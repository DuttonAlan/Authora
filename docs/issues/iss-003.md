# ISS-003 – Deleted Users can still be changed, including getting the administrator Role

- **Status:** Resolved (2026-10-11)
- **Found:** 2026-10-11, in the code review of `feature/add-identity-endpoints`
- **Area:** Users (`UpdateUserService`, `UnlockUserService`, `RevokeUserSessionsService`, `AssignRoleService`, `RemoveRoleService`)

## Problem

Deleting a User is a soft delete: the User is set to `UserState.Deleted` and kept for history. But only `ActivateUserService` and `DeactivateUserService` checked for this state. All other endpoints that change a User still worked on deleted Users:

- `PUT /api/users/{id}`
- `POST /api/users/{id}/unlock`
- `POST /api/users/{id}/revoke-sessions`
- `PUT /api/users/{id}/roles/{roleId}`
- `DELETE /api/users/{id}/roles/{roleId}`

## Impact

- A deleted User could get the administrator Role. Any later way to bring the User back (e.g. a restore feature or a direct state change in the database) would bring back a privileged account.
- The history of a deleted User could be changed after the deletion, e.g. its Name, Email or Roles.
- The lifecycle rules were inconsistent: activating a deleted User returned 409, but changing it returned 204.

## Cause

Each service checked the User state on its own, and only the activate and deactivate services did. There was no shared rule that a deleted User cannot be changed.

## Fix

- New `DeletedUserGuard.EnsureNotDeleted(user)` in `Core/Application/Users`, which throws `ConflictException` (409) with `A deleted User cannot be changed.`
- The five services above call it right after loading the User.
- The API documentation of these endpoints lists the new 409 response.

Unchanged on purpose:

- Reading a deleted User, its Roles and its Permissions still works, because the record is kept for history.
- Deleting an already deleted User still returns 204 (idempotent).
- Activate and deactivate keep their own, more specific messages.

## Verification

Tested manually against a fresh database, with a User that has the Role `editor` and was then deleted:

| Request on the deleted User | Result |
|---|---|
| Update the First Name | 409 |
| Unlock | 409 |
| Revoke sessions | 409 |
| Assign the `admin` Role | 409 |
| Remove the `editor` Role | 409 |
| Activate | 409, `A deleted User cannot be activated.` (unchanged) |
| Delete again | 204 (unchanged) |
| Get the User and its Roles | 200, `state: Deleted`, still has `editor` |

The same requests on an active User still return 204.
